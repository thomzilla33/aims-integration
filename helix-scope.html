Three behaviours that were missing everywhere — now in V1

AActivation gate

A source is unusable until every field is resolved or ignored. Visible blocking state, live unresolved count, and an Activate control that is disabled with its reason stated — never a mystery button.

Absent from every prior artifact.

BDrift as normal flow

An active connector gains a new field and loses a previously-mapped one. Both return to the queue with distinct treatments — routine operation, not a failure. Triggerable live from the demo controls.

Previously styled as an error, if shown at all.

CCross-tenant clone + diff

Clone a resolved mapping to a second tenant — standard carries over resolved, custom lands pending — and diff the same connector across two tenants so divergence is visible.

No cross-tenant story existed before.

How to walk the team through it

The 90-second demo · zero dead ends

  1. Connect — add a spreadsheet / SFTP source (certified setup).
  2. Map — open a pending connector; the activation gate is closed.
  3. Resolve — accept, create, or ignore each custom field.
  4. Activate — the gate opens; the source goes live.
  5. Clone → diff — copy the mapping to a second tenant and compare.
connect → map → resolve → activate → clone → diff
